# 2026-08-12 — 探店地址册

## 完成

- 新增“探店”本地地址册，仅用于记录已去过的餐厅。
- 餐厅记录包含名称、省、市、区、详细地址、菜系、人均、推荐菜、备注和最多两张照片。
- 页面采用“城市地址册”布局：省份索引、城市索引，以及按“省 · 市 · 区”分段的餐厅小票卡。
- 支持按店名、菜系、地址和备注搜索；点击卡片可编辑或删除；可一键复制餐厅名和完整地址。
- 数据保存到用户隔离的 IndexedDB `foodmap_v1`；兼容 IndexedDB 不可用时的 localStorage 回退。
- 探店照片支持选择上传及剪贴板粘贴，沿用页面既有压缩流程。
- 新增浏览器端中文 OCR：探店与下厨均有独立的截图上传／拖拽／聚焦粘贴入口；识别结果先在可编辑草稿区呈现，支持复制或由用户确认采用。
- OCR 使用 Tesseract.js 在浏览器运行，首次使用需要下载并缓存中文语言模型；识别结果仅作草稿，仍需用户确认后保存。
- 下厨表单优化为两个独立入口：菜品照片与截图识别。上传框明确标示点击、拖拽或聚焦后粘贴；不再在编辑文字时全局拦截图片粘贴。
- 下厨 OCR 结果显示为可编辑的独立预览文本，支持“采用到教程文字”“复制文字”及“不采用”，不会自动改写教程输入框。
- 探店确认采用 OCR 草稿后，才会辅助填入店名、地址、人均、菜系，并将完整原文追加到备注；省、市、区始终由用户确认填写。
- OCR 识别前新增本地放大、灰度化、Otsu 自适应二值化和对比度强化，并使用段落型中文排版识别模式，改善小字、浅色背景与复杂截图的识别效果。
- 新增旅行档案第一层：本地创建、编辑、删除旅行项目，保存目的地、日期、同行人、交通住宿、按天行程及攻略提醒。
- 旅行总览以旅行册封面呈现；打开档案后按交通住宿、逐日行程、攻略提醒查看，数据使用用户隔离的 IndexedDB `travel_v1` 保存。
- 旅行档案表单新增“导入已有攻略”：支持本地读取 PDF、Word（docx）、TXT、Markdown 和图片；导入结果均先呈现在可编辑草稿区，可复制或追加到行程／攻略提醒，不会覆盖已有内容。
- 文本型 PDF 与 Word 直接提取文字；图片沿用本地增强 OCR。扫描版 PDF 无内嵌文字时，需要导出为图片后再识别。
- 旅行攻略草稿升级为结构化智能填充：解析日期区间并计算天数/晚数，识别旅行名称、目的地、交通住宿、章节和 Day/第几天行程；导入后先展示字段摘要，再一键填入当前空字段，避免覆盖已有手动记录。
- 旅行档案总览移除列表区域重复的“新建旅行档案”按钮，保留页面标题右侧的主操作入口。
- 新增 Vercel Serverless Function `api/parse-travel.js`：通过服务端 OpenAI Key 将攻略文本解析为固定 JSON 字段（名称、目的地、日期、天数、同行人、交通住宿、逐日行程、提醒）。
- 网页新增“AI 结构化解析”入口，解析后展示字段摘要；“一键填充所有字段”优先采用 AI 结果并仍不覆盖手动填写的内容。本地 `file://` 使用时会明确提示需先部署到 Vercel。
- 新增 [travel-ai-setup.md](travel-ai-setup.md) 与 `.env.example`，说明 Vercel 环境变量配置；未部署和未配置密钥前不能进行真实 AI 端到端调用。
- 根据用户已有服务，将旅行解析后端从 OpenAI 改为 DeepSeek：使用 `DEEPSEEK_API_KEY`、`deepseek-chat` 与官方 JSON Output 模式；服务端校验返回的关键数组结构后再交给网页填充。
- 修复 Vercel 发布入口：新增 `vercel-build`，将 `docs/` 的完整档案馆页面复制为部署静态输出，并显式配置 Vercel 使用该输出目录；临时构建目录 `.vercel-output` 已忽略，不会提交。
- CloudBase 同步第一阶段：新增 Vercel 服务端同步接口，使用 CloudBase PostgreSQL 保存按 Supabase 登录邮箱隔离的完整档案快照；网页登录后会优先读取云端记录，云端不存在时自动备份本机 IndexedDB 数据，后续修改将延迟自动同步。腾讯云密钥只保存在 Vercel 环境变量中。
